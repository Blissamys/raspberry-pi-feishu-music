# 下载专用 U 盘 → 播放器 SD：设计草案

状态：用户已确认去重规则及两盘 UUID；本地实现与 85 项测试完成，待部署/真机预览批准。未改线上或真实音乐存储。

## 需求与已核实差距

固定 U 盘保存下载音乐，播放器 SD 临时插入后从 U 盘整体增量导入，避免曲库重复。这里将“歌单”暂理解为 SD 内的音频曲库，不生成 M3U 播放列表。

现有 download_core/export 的 inbox 路径均固定为用户家目录；主入口启动还会 mkdir。导入按标签优先、否则第一个合适 USB 分区选择；不能直接用于两个盘的角色区分。rsync 只有路径级同步和缓存过滤，没有歌曲级去重。

## 建议交互

一次性只读识别两块盘，用户明确指定下载 U 盘与播放器 SD，按分区 UUID 保存角色；不以 sda/sdb、插入顺序或仅卷标认盘。重新格式化或换卡后重新绑定，UUID 冲突或同一设备则拒绝。

日常：

1. `导入预览`：验证两盘身份、挂载位置、目标容量，扫描 U 盘曲库及 SD 上已有音频，返回新增、重复、待处理冲突和所需空间。不复制/删除音乐。
2. `确认导入`：执行本用户最新预览计划；重新核对设备与文件状态，变化时拒绝旧计划并要求重新预览。完成后同步并安全卸载目标 SD；卸载失败不得提示可拔卡。

辅助：`存储` 查看角色/连接/容量；`进度` 保留任务查询并显示复制进度；`弹出SD` 只卸载绑定的目标 SD，任务进行中拒绝。下载 U 盘保持挂载。双盘模式下旧“导入”映射到预览；本地模式保留旧直导。

## 下载目的地

搜索/下载通过统一存储解析器访问下载 U 盘固定子目录；列表、删除本地、系统状态使用同一解析器，不能各自保留不同常量。没有配置双盘模式时保留原有本地模式；启用双盘模式后，U 盘不在、UUID 不符、挂载失败或只读均明确报错，不能悄悄写回系统卡上的同名空目录。原本机 inbox 的迁移另行处理，不自动搬移或删除。

`歌曲…` 仍立即下载；普通自然语言仍先候选后确认。部署或服务重启另需明确批准。

## 去重（已选方案 A，方案 B 仅为讨论记录）

方案 A：优先使用音频标签的歌名＋歌手识别歌曲；同曲不同编码/音质也跳过，保留 SD 已有版本。保留 live/remix 等版本词，不做激进模糊折叠。标签缺失或有歧义时不能凭目录名猜测；使用相同文件内容的哈希证据，否则列为待处理冲突。首次预览需让用户了解该规则可能合并不同录音。

方案 B：只按文件内容哈希识别完全一致的文件；最确定，但不同编码/音质同曲仍可能共存。

两方案均扫描源盘内部的重复和目标上已有歌曲，而非仅比较相同路径。已在 SD 上的历史重复项仅报告；不自动删除或替换。因而当前范围只能保证不新增按所选规则判定的重复，不能声称自动清空了所有历史重复。

## 复制与边界

只处理音频及关联歌词，不拷 pkl、缓存或未完成下载。目标临时文件复制并校验成功后再发布最终文件；同名不同内容不覆盖，转为冲突；禁止 rsync --delete。空间不足时在写入前拒绝，处理中断保留源音乐，不将部分文件记为成功。

设备校验排除 mmcblk0；拒绝源目标相同/嵌套、角色交换、意外挂载路径、符号链接越界。下载、删除、导入、挂载/卸载应使用统一任务协调，防止预览与复制期间曲库被改动。无关盘不挂载/卸载，不格式化盘；不擅改 systemd/fstab 或 sudoers。

## 验证计划

临时目录和虚构设备覆盖：两 USB 顺序交换、缺盘/换盘、同 UUID、源目标相同、缓存过滤、源内重复、目标已有重复、同名不同内容、元数据不足、空间不足、中断/重试、预览过期、卸载失败、固定下载口令与白名单。

获得明确设备身份和部署批准后才进行真机验收；文件系统兼容性、实际挂载权限和 SD 导入/播放器播放必须现场验证。
