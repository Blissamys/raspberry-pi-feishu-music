# 搜索、导入状态和去重冲突交互优化

用户已要求实现三处产品优化；先本地实现和测试，未经再次明确批准不部署或重启。真实音乐不用于写操作测试。

- 搜索：候选显示来源、标题中的版本词及源站标注格式/大小。保留来源不同的同曲，并轮流展示各源；缓存最多 20 条，每页 3 条。换一批/上一批不重新发网络搜索；只搜某源/重新搜索可复用该用户关键词。十分钟过期，取消清理候选。歌曲前缀维持第一条立即下载。
- 导入：扫描中→等待确认→复制中→校验中→安全卸载中→完成；当前文件、计数/字节与耗时可通过进度查询。失败说明已完成数量和下一步；卸载失败不提示可拔。未处理冲突可跳过，不阻止其它已确定新增项导入。
- 冲突：稳定编号、分页列表和详情。标记同曲/跳过冲突仅作用于本次计划；确认新增仅允许元数据不确定但目标路径无冲突的项。不得绕过同名保护、设备校验、空间检查、十分钟有效期或曲库变化检查。处理后不立刻复制，仍需确认导入。

文件：download_core.py（多源结果）、search_ui.py（候选呈现/分页）、library_sync.py（结构化冲突/决定/进度）、commands.py、feishu_bot.py、相应 tests 与文档。

步骤：新增失败测试→实现搜索→实现冲突决定→实现阶段进度与 bot 接入→全量测试和独立安全审查→更新文档→提交具体部署清单供用户批准。源站返回空结果不能据此宣称源站故障或没有收录；没有真实下载文件不能报告下载成功。
